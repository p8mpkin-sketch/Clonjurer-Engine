# 引擎速度基准 · 自动化优化循环

只针对引擎模块（`core/cloner_engine.py`、`core/pattern_detector.py`、`core/pixel_calibrator.py`）的纯计算路径，度量速度与效率，并在每轮优化后自动打分。无需浏览器和网络。

## 用法

```bash
python3 engine_bench/perf/loop.py --label "本轮改动说明"   # 测试闸门 + 跑分 + 记账
python3 engine_bench/perf/loop.py --watch 300               # 常驻：引擎文件一改就重跑
python3 engine_bench/perf/bench.py --only score_long,css_refs  # 只跑部分基准
```

每轮结果追加到 `history.jsonl`，并与历史最佳比较（回退超过 5 分会告警）。

## 0–100 分怎么算

| 规则 | 说明 |
|---|---|
| 基线 | `baseline/` 里冻结的优化前引擎代码（commit 8a0cf35），与当前代码在同一进程、同一夹具上交替运行，机器噪声对两边相同 |
| 单项提速 s | 基线耗时 / 当前耗时；每项至少跑 repeat 次（快项自适应加采样到 ≥3 秒），取最小耗时 |
| 单项得分 | `100 × clamp(ln s / ln 3, 0, 1)`：1x = 0 分，1.73x = 50 分，3x 及以上 = 100 分 |
| 总分 | 按权重加权平均（权重按真实任务中的调用频次与耗时占比设定） |
| 正确性闸门 | 每项输出必须与基线逐字节/逐值一致，否则该项 0 分；单元测试（含差分模糊测试）不通过则总分 0 |

## 基准项

| 名称 | 权重 | 内容 |
|---|---|---|
| score_long | 3 | 长页评分 v3（1440×9000 级截图，~6MB PNG）。修复循环常态：参考图固定，克隆图每次都是新文件 |
| score_long_cold | 0 | 同上但两张图都是新文件（只展示，不计分） |
| score_view | 1 | 首屏评分（1440×900） |
| localize_html | 3 | HTML 本地化重写（1.5MB，~1200 条替换对 + 导航改写 + 注入） |
| rewrite_js | 3 | JS 包本地化重写（3MB） |
| css_refs | 1 | CSS 引用解析（1MB） |
| text_score | 1 | 文本 F2 指纹（200KB 中英混排） |
| compose_pairs | 1 | 替换表构造（400 个资源） |
| pattern_detect | 2 | 框架模式识别（6×2MB JS 全量扫描 + 渲染 DOM） |
| calib_cells | 1 | 像素校准网格差分 |
| srcset | 1 | srcset 解析 |

截图类基准里，克隆图每次调用都换成像素相同、字节不同的新文件（插入 tEXt 块），保证它不命中任何缓存；只有任务内固定不变的原站参考图会被缓存复用，这与引擎真实调用一致（每轮修复评分、校准后重评分、保真轨评分都用同一张参考图）。

## 正确性

`tests/test_perf_equivalence.py` 把每个被优化的函数与冻结基线做差分模糊测试（导航改写 4000 例、替换表 1500 组、CSS 6000 例、URL 快速路径 20000×6 例、随机尺寸/模式截图评分与热力图像素、校准、模式识别 200 个随机工作区、校准预热与延迟热力图等价），并覆盖 Unicode 大小写折叠陷阱（İ ı ſ K）、超长键、同路径改写后缓存失效等边界；另有 AI 修复的补丁消毒与回滚守卫用例。合计 21 个用例。
