## 2. 评分口径

自动化基准位于 `engine_bench/perf/`，口径固定、可复现：

- **基线**：`engine_bench/perf/baseline/` 冻结的优化前代码（commit 8a0cf35），与当前代码在同一进程、同一夹具上交替运行，机器噪声对两边相同；每项取多次运行的最小耗时。
- **单项得分**：`100 × clamp(ln 提速 / ln 3, 0, 1)`。提速 1 倍 0 分，1.73 倍 50 分，3 倍及以上 100 分。
- **总分**：按权重加权平均（权重按真实任务中的调用频次与耗时占比）。
- **正确性闸门**：某项输出与基线有任何不同，该项记 0 分；单元测试不通过，总分记 0。
- **截图类基准的调用方式**与引擎修复循环一致：原站参考图在任务内固定，克隆截图每次都是新文件（不会命中缓存）。两张图都是新文件的“冷启动”项单独展示、不计分。

## 5. 做了什么

### 本地化重写（HTML / JS / Mock 响应体）
- **替换表前缀树正则**：上千条 URL 变体原来是扁平交替 `k1|k2|...`，每个字符位置都要逐个试配；改为前缀树正则后，每个位置只沿一条字符路径前进。两者都是“最左起点取最长命中”，结果相同。编译结果按替换表缓存，多页面和多个 JS 文件共用一次编译。替换表不是按长度降序排列，或者含空键时，回落旧写法。
- **导航逃逸改写锚点扫描**：`top.location` / `parent.location` 三条正则以交替开头，无法用前缀加速，3MB JS 每趟约 120ms。现在先用 `str.find` 定位字面锚点，只在锚点处匹配，与 `re.sub` 的“最左、非重叠”语义完全一致。

### 框架模式识别
- JS 字节和渲染 DOM 各转一次小写，纯字面量指纹用 `in`（C 层子串查找），其余使用小写化后的正则，不再走 `re.I` 全量扫描。
- Unicode 下 `re.I` 会让 İ、ı、ſ、K 与 ASCII 字母互配；DOM 文本含这些字符时整体回落旧路径。

### 评分（诚实相似度 v3）
- 两张截图并行解码与缩放（PIL 的 PNG 解码和重采样会释放 GIL）。
- **参考图缓存**：512 宽缩放结果，以及参考图侧的边缘掩码、NCC 去均值块，都按文件内容 sha1 缓存。修复循环中每任务要评分 4–8 次，参考图不变；文件被改写则键变化，不会读到旧数据。
- 只有一张图要解码时，横向重采样按行分 3 带、纵向按列分 3 带并行。PIL 的 resize 是可分离两趟，各行、各列互相独立，分带结果逐字节相同。
- 边缘 IoU 改为 numpy 向量化，复刻 PIL `FIND_EDGES`（1px 外框保留原值）和 `MaxFilter`（边缘复制扩边）的边界语义。
- 文本通道只计算 |A|、|B|、|A∩B| 三个数：CJK 二元组编码为整数并用 numpy 去重求交，拉丁词用字节翻译表分词；原站文本只算一次。
- 差异热力图分 3 带并行生成，numpy Sub 滤波后分片 deflate 拼成一个合法的 zlib 流（pigz 同款做法）直接写 PNG。

### 像素校准
- 336 个格子的均值和方差改为一次向量化求和：行内用 float32 累加（每行部分和小于 2^24，结果精确），跨行用 float64，套 ImageStat 的同一公式，结果逐位相同。
- 参考图的格子统计按内容哈希缓存；原站侧全是内容格时，克隆图不必解码。

### CSS / srcset / 替换表构造
- CSS 三条引用正则改为锚点扫描；已收录的引用先查重，免去重复 `urljoin`。
- 严格形态的绝对 http(s) URL（小写 scheme、ASCII、无 `; #`、空白和控制字符）走 `urljoin`/`urlsplit` 快速路径，其余回落 urllib。
- 替换表构造先整批校验 URL 形态，变体直接取切片；长度降序的稳定排序改用内置 `len` 作 key。

## 6. 行为变化（请留意）

1. **差异热力图文件编码不同**：`diff_preview.png`、`fidelity_diff.png` 改为自行编码，解码后像素与旧版完全相同，体积相当，只是文件字节不同。
2. **评分新增进程级 4 线程池和小型缓存**：缩放结果最多 4 张，参考图中间量最多 2 份，校准统计最多 8 份。键都是文件内容 sha1。所有池任务都是叶子任务，调度器多 worker 并发评分不会死锁。
3. **端口可配置**：`config.py` 新增 `CLONER_HOST` / `CLONER_PORT` 环境变量（默认仍是 127.0.0.1:8899），`CLONER_PUBLIC_URL` 的默认值随端口变化。同一台机器可以并行运行多个独立实例，例如：
   ```bash
   CLONER_PORT=8898 python3 app.py
   ```

## 7. 测试

- 新增 `tests/test_perf_equivalence.py`（16 项），把每个被优化的函数与冻结基线做差分模糊测试：
  - 导航改写 4000 例、替换表 1500 组、CSS 6000 例、URL 快速路径 2 万 × 6 例、替换表构造 400 组；
  - 随机尺寸和模式（RGB/RGBA/L）的截图评分明细与热力图像素；
  - 校准、模式识别各 200 个随机工作区；
  - 边界情况：Unicode 折叠陷阱、超长键（不触发递归溢出）、同路径改写后缓存失效、热力图 PNG 严格校验（CRC + adler32）。
- 合计 39 项，运行：`python3 -m unittest discover tests`

## 9. 已知限制与后续方向

- 首屏和长页评分剩余耗时以克隆截图的 PNG 解码为主，单图解码无法再并行；云主机上这两项的提速会在 2.7–3.5 倍之间浮动。
- 后续可做：评分完成后，把克隆图的校准网格统计顺带算好，免去紧随其后的校准再解码一次（真实流程有收益，但当前基准不体现）。
